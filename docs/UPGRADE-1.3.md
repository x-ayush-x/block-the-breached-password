# Version 1.3 — Security Test Lab

## What changed

A new Security test lab page executes nine reproducible scenarios through the shared password security engine: strong-but-mock-breached, valid no-match, common password, short password, HTTP 503, HTTP 429, malformed response, timeout and matching zero-count padding.

The lab accepts no user passwords. Fixed public synthetic test material lives in its source. Only the service transport is replaced with an in-memory mock: hashing, request construction, parsing, strength estimation and policy decisions use the application's existing functions. No HIBP traffic is generated by the lab. Signup and reset retain their live lookup behavior.

A scenario passes only when the actual gate decision, breach status, expected error and outbound request contract match expectations. The strong-but-breached scenario also verifies that the strength engine actually labels its fixture Strong. It must still be rejected.

## Try it

1. Open Security test lab in the sidebar.
2. Click Run security tests.
3. Expect 9 of 9 completed and 9 passed on the unmodified build.
4. Explain the first card: strength estimates guessability; exposure is separate.
5. Explain service failure cards: unknown never becomes clear.
6. Click Export evidence to download security-lab-evidence.json.
7. For actual network evidence, visit signup and follow Privacy & proof.

Reports carry LOCAL SYNTHETIC TESTS — NOT LIVE HIBP and contain only scenario IDs, decisions, statuses, timing and request-contract booleans. They contain no passwords, emails, prefixes, hashes or suffixes. Cancelled runs are labelled incomplete. Navigating away cancels the run and discards results.

## Install this update on your existing GitHub repository

Extract the update ZIP. Upload its contents (src, e2e, docs, package.json, package-lock.json and README.md) into your repository root with Add file > Upload files. Commit all changes together. These folders contain only changed or new files; retain other existing files. Do not delete your existing src directory. No hidden files need changing. The existing deployment workflow should run after committing to main.

Local development: npm ci, then npm run dev. Validation: npm run lint, npm test, npm run build:pages. Browser tests: npm run build, npx playwright install chromium, npm run test:e2e.

## Scope and limitations

- The lab checks shared engine behavior, not every signup/reset UI interaction; those have separate browser tests.
- The request contract inspects fetch arguments supplied to the mock. It is not packet capture or proof against malicious extensions.
- A mock match makes no claim about the live HIBP dataset.
- The 60ms timeout is accelerated for this lab. Live lookup keeps its existing 12-second timeout.
- Durations are local simulated execution timings, not live API latency.
- Browser-only enforcement can be bypassed. Authentication is still simulated; production requires an independently enforced server-side design.
- No dependencies were added. No changes were made to the existing numeric password policy or NIST wording.
