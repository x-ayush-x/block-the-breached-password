# 1.7.0 — Understand the dashboard

Date: 2026-10-04. Baseline: v1.6 including the narrow-screen hotfix. Status: [pull request #5](https://github.com/x-ayush-x/block-the-breached-password/pull/5); not merged or deployed by this update.

Application: 1.7.0. Policy: `hello-world-1.5`. Report schema: `hello-world-report-1`.

## Purpose

The dashboard previously showed many counters without making the denominators obvious. This update explains a run's actual arithmetic, separates coverage from match rate and keeps optional technical detail accessible without crowding the initial view.

## Added

- `explainDashboard()` pure helper and `DashboardExplanation` component for current counts, coverage, lifecycle-sensitive next steps and definitions.
- Worked example and extensive setup, architecture, security, reporting and troubleshooting material in the README.
- Consolidated changelog covering the retained release history; detailed release-record process and template.
- Tests for complete, partial, empty and cancelled runs, mock wording, on-screen calculation, expandable panels and print/report consistency.

## Changed

- Dashboard headings guide users through configuration, interpretation and report retention.
- Donut center displays checked/total; rate card still uses matched/successfully checked. The ring continues to represent all inputs.
- Dataset composition and performance counters moved into native expandable details; no data or existing controls removed.
- Mock report sentences explicitly refer to the local mock corpus across screen, JSON and print.
- Updated application version labels. Policy/schema identifiers remain stable because decision rules and report structure are unchanged.
- Historical v1.1–v1.3 guides carry context notices where later offline-mode behavior differs.

## Fixed

- Ambiguous donut-center rate versus ring denominator.
- Real-breach language in mock report sentences.
- Outdated README placeholders, scattered version notes and incomplete source/command documentation.

## Removed

No application features or dependencies removed. The repeated long dataset explanation was consolidated into the existing expandable composition section.

## Security and compatibility

The lookup service, password security hook, policy, hashing, benchmark and comparison validator retain their existing contracts. Explanations derive only from aggregate counts; they never authorize a password. No new storage, analytics, credentials, account import or external service was introduced. Authentication remains simulated. Live failures never trigger mock fallback. Pages configuration and the v1.6 hotfix are retained.

Older supported dashboard reports remain importable; compatibility still depends on source, dataset, policy, scenario and full coverage. Mock report prose changes, but schema/count fields do not. All password rules remain unchanged.

## Upgrade and rollback

Use [macOS instructions](../UPGRADE-1.7-MACOS.md). The update-only ZIP targets v1.6 (the earlier layout fix is included where needed). Preserve a backup before copying files. No files need deleting. To return to v1.6, stop the server and reopen the saved v1.6 project. Reports are standalone user-selected downloads, not an application database to migrate.

## Known limitations

No production authentication, employee-directory audit, real-password upload, persistent history or guaranteed offline hosted reload. The large deferred zxcvbn chunk advisory remains. Native Save as PDF and a full screen-reader audit are outside automated coverage. Old notes are historical; this release makes no new NIST certification or live-service availability claim.
