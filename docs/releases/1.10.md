# 1.10.0 — Clear signup and reset decisions

Date: 2026-10-05. Baseline: v1.9. Publication: v1.10 release branch; merge and deployment are separate steps.
Application: 1.10.0. Policy: `hello-world-1.5`. Dashboard schema: `hello-world-report-1`.

## Problem and outcome

The form repeated length, strength and breach information in multiple lists. Its password-only decision message could sound ready while email or confirmation still prevented submission. A consolidated checklist now explains each requirement and the next action for the complete form.

## Added / changed

- Requirement rows for length, local common/account-related values, breach result, email context and reset confirmation.
- Met, Needs attention and Pending labels, plus an explicit Ready to simulate / Not ready yet summary.
- Next-action guidance for empty input, local rejection, in-progress lookup, breach match, service failure, expiry, unchecked password, invalid email and confirmation.
- Strength remains visible and explicitly advisory. Processing stages remain real, now behind a native disclosure.
- Submission button references guidance using aria-describedby.
- README, release records, macOS instructions and version labels updated.

## Fixed / removed

Whole-form readiness now accounts for email and confirmation. Duplicate local-rule and decision lists were removed; the consolidated checklist retains their information. No request, export, privacy evidence or checking capability removed.

## Security / compatibility

This is a presentation change. The submit handler still independently calls decisionNow to enforce freshness and checks email/confirmation. HIBP service, hashing, policy, hooks and report schemas are unchanged. No additional requests, storage, analytics or dependencies. Authentication remains simulated. Source switching remains explicit with no silent mock fallback. Pages workflow/base path/CSP unchanged.

## Migration / limitations

Use the complete ZIP or apply the update-only ZIP to v1.9. See [macOS instructions](../UPGRADE-1.10-MACOS.md). No file deletions required. Keep a backup.

Browser checks can be bypassed; UI clarity is not production authentication enforcement. Mock no-match results do not establish real-world safety. Native print dialogs and a full screen-reader audit remain outside automated coverage. The deferred strength-library chunk-size advisory remains.
