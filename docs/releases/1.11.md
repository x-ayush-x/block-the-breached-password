# 1.11.0 — Understand report comparisons

Date: 2026-10-05. Baseline: v1.10. Publication: v1.11 release branch; merge and deployment are separate steps.
Application: 1.11.0. Policy: `hello-world-1.5`. Dashboard schema: `hello-world-report-1`.

## Problem and outcome

A single comparison sentence did not explain the contents of the files or all the reasons a comparison was blocked. The new view displays report metadata, source and coverage beside a five-part compatibility checklist.

## Added / changed

- Side-by-side file summaries, loading/empty/error states and individual Remove buttons.
- Compatibility checks for source, dataset/size, policy, scenario and complete successful coverage. The existing comparison function uses the same checks.
- Help distinguishes JSON imports from printed PDFs and explains percentage points and limits of mock/live comparisons.
- Removing or replacing a file invalidates pending reads; unmounting invalidates both slots.
- Application version included in dashboard JSON and print reports; no schema or policy change.
- README, changelog, macOS instructions and release evidence updated.

## Fixed / removed

Blank dataset/policy identifiers and unexpected live-scenario values are rejected. Legacy absent live scenarios normalize to null, matching the current export shape. No functionality removed.

## Security / compatibility

No upload or network request for comparison. File-size limit remains 1 MB. Parsing retains only allowlisted metadata/counts; imported account rows are discarded. Malformed files cannot retain a previous valid comparison. Files are self-reported and unauthenticated; matching identifiers cannot prove provenance. Partial, cross-source or different-dataset comparisons stay blocked. Separate live runs remain different datasets.

Hashing, breach service, security hooks, password policy and authentication behavior are unchanged. No new dependencies, analytics or credential storage. GitHub Pages configuration is unchanged. Dashboard exports gain additive version metadata; comparison still supports the existing report schema. Lab reports and PDFs are not dashboard comparison inputs.
