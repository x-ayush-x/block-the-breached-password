# 1.8.0 — A usable demo guide

Date: 2026-10-04. Baseline: v1.7. Publication: v1.8 release branch; merge and deployment are separate steps.
Application: 1.8.0. Policy: `hello-world-1.5`. Schema: `hello-world-report-1`.

## Purpose

The global offline-mode banner took too much space and combined source selection, instructions and readiness into an unclear block. This release makes source selection compact and moves presentation help behind an explicit Demo guide button.

## Added

- Check source selector: Live HIBP / Practice · mock data.
- Five individually selectable guide steps with action links and Do this / Explain this text, Previous/Next buttons and Escape-to-close focus restoration.
- Readiness and challenge mapping available within the optional guide. Readiness checks secure context, Web Crypto and a network hint without a request.
- Footer identifies app version, policy and build. Vite embeds the first 12 characters of GitHub's GITHUB_SHA if available, otherwise `local`. No additional network call or backend is used.

## Changed / fixed

- Page-aware source descriptions explain that dashboard mode is selected separately and Lab responses always mock.
- Source switching warns about clearing data and announces the selected mode. Existing keyed page remounts still cancel pending requests and clear state.
- Privacy guide opens signup, not the separate Privacy page, to keep current check evidence available for inspection.
- Mock guidance explicitly requires a manual switch to live mode to obtain real network evidence. The guide never runs a check or asserts a step was passed.
- README, changelog, update instructions, version labels and test interactions updated.

## Removed

The old banner/checkbox UI is replaced; no checking, reporting, readiness or offline-practice capability is removed.

## Security / compatibility

No new dependencies or storage. HIBP checking, policy, freshness, hashing, Lab engine and reports retain their existing behavior. Authentication remains simulated. Changing source aborts work rather than moving a result between sources. No silent mock fallback. Build ID is an identifier, not authenticity proof. Local builds may not identify a Git commit.

The Pages base path, deployment workflow and production CSP remain intact. Vite changes only to inject build identification. Policy/schema versions are unchanged; report compatibility rules remain unchanged.

## Validation

- `npm run check`: lint, 84 unit/service tests and standard production build passed.
- Full Chromium browser suite: 41 tests passed on macOS. After the final wording/test-assertion adjustment, all 3 v1.8 browser tests passed again.
- `npm run build:pages`: passed; generated repository asset base and production CSP verified. Restored the standard build for local preview.
- Compared existing services, hooks, utilities and GitHub workflows against the v1.7 baseline: unchanged.
- Visually inspected actual light/dark desktop screenshots and the expanded guide at 320px; no clipped controls or horizontal overflow. See [screenshots](../screenshots/v1.8/README.md).
- Browser tests mock HIBP; these results do not verify current live-service availability. These are local packaging-time results; the GitHub pull request provides Linux CI results for the published branch.
- The existing deferred strength-library chunk-size advisory remains; it does not fail either build.

## Migration and limitations

Apply the update ZIP over v1.7 or use the complete project. See [macOS instructions](../UPGRADE-1.8-MACOS.md). No files need deleting. Retain a backup for rollback.

The guide is manually navigated, not a verifier of presentation completion. Readiness cannot establish HIBP reachability. No service worker or guaranteed offline hosted reload; keep the local server running. Native PDF dialog and a full assistive-technology audit remain outside automated coverage. The deferred zxcvbn size advisory remains.
